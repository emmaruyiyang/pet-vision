# `docs/` — the published site

This folder is what GitHub Pages serves, which is why it is called `docs/` and not
`viz/`: branch-based Pages can only publish from the repository root or from `/docs`.
It holds the two motion visualisations and nothing else.

Two static pages that play back in the browser. Everything they draw comes from CSVs
that already exist; no new model, nothing re-segmented.

```
docs/
├── index.html            the contents page
├── gaze-by-scene/        ① stimulus gaze: heat map + scanpath
│   ├── data.json         written by scripts/export_gaze_web.py
│   ├── stim/             19 stimuli, downscaled
│   └── heat/             19 heat maps, rendered separately
├── live-aoi/             ② the walk: video + per-second indicators
│   └── data.json         written by scripts/export_aoi_video_web.py
├── media/
│   └── walk-05-10.mp4    74 MiB — the one copy, shared by both uses
├── serve.py              static server WITH byte-range support
├── .nojekyll             so GitHub Pages serves these files verbatim
└── standalone-build/     generated by scripts/bundle_viz_html.py, git-ignored
```

This folder is self-contained: it is the whole site, 84 MB, and nothing in it reaches up into
the project. The three scripts that write into it stay in `scripts/` with the rest.

```bash
python3 docs/serve.py          # http://localhost:8777
```

Use this server, not `python3 -m http.server`. The latter ignores HTTP Range, so the
`<video>` plays from the start and the scrubber does nothing — and the clip is 77 MB.

## If you just want a file to double-click

The pages are plain HTML; the only reason they need a server is `fetch("data.json")`, which
the file:// origin blocks. To fold that away:

```bash
python3 scripts/bundle_viz_html.py              # both
python3 scripts/bundle_viz_html.py gaze-by-scene
```

It writes to `docs/standalone-build/`, which is generated and git-ignored — publishing the
site does not need it, because `fetch` works fine over http:

| File | Size | Needs anything beside it |
| --- | --- | --- |
| `gaze-by-scene.html` | 5.1 MB | no — all 38 stimulus and heat-map images are inlined as `data:` URIs |
| `human-dog-live-aoi.html` | 93 KB | yes, `walk-05-10.mp4`, which the bundler copies in beside it |

The video stays a real file on purpose. Base64 would make it ~100 MB of text to parse before
the first frame, and some browsers refuse a media `data:` URI that large. It costs nothing:
over file:// the browser reads the file directly, so seeking works — which is exactly what
it cannot do under `python3 -m http.server`.

Both pages prefer an injected `window.__DATA__` and fall back to `fetch`, so the sources in
`gaze-by-scene/` and `live-aoi/` keep working under the server unchanged. Re-run the bundler
after editing either page.

## ① `gaze-by-scene/` — heat map + scanpath

All 19 trials, switched by scene. Pick a scene and its three conditions — human eye height,
dog eye height, dog height through a dichromat transform — sit side by side in one row, one
column each. A condition a scene never got keeps its column and says "never shown", so the
three plates stay in the same place as you move between scenes.

The **View** control swaps every plate between two readings of the same trial. It opens on
the heat map — the settled answer for a trial — and the scanpath is the second look, at how
he got there.

* **Heat map** — the trial summed over its whole duration, rendered separately into
  `gaze-by-scene/heat/`. Each plate is normalised **within itself**, so colour says where he
  looked in that plate and never how much against the plate beside it.
* **Scanpath** — the live trace. The bright point is gaze now, the trail behind it fades over
  an adjustable 0.3–8 s, and the ring radius tracks how still gaze has been over the last
  250 ms: wide ring ≈ fixation, thin line = saccade. A plate whose trial has ended draws its
  whole path. Space plays and pauses, arrows step ±0.5 s.

`H` toggles between the two. Playback controls dim in heat map view, because nothing moves.

Under each plate, the same numbers either way: a stripe splitting that trial's dwell across
classes, then the top five classes reaching 1% dwell, each with its dwell share and, on the
right, **dwell minus the class's share of the image, in percentage points** — `+31` means it
took 31 points more of his time than its area alone would predict.

Two things to read it with:

* The homography is estimated from the monitor's own outline, not from AprilTags, so a
  fixation is good to tens of stimulus pixels, not single ones.
* The rectified screen comes out at aspect 1.43 against the stimulus's 1.78
  (`viewer/data/<session>.surface.json`), so **vertical** positions in this session are
  compressed by about 20%; horizontal is unaffected.
* n = 1 (P01). This is the pipeline running end to end, not a population result.

Re-export the data:

```bash
python3 scripts/export_gaze_web.py
```

It reads `viewer/data/<session>.gaze_px.csv` (already mapped into stimulus pixels),
`eyetracking_n1/P01_trials.csv` (trial boundaries), `aoi/gaze_aoi_shares.csv` (per-trial AOI
shares) and `<session>.surface.json` (the aspect figure above), decimates gaze to ~60 Hz,
writes a 1280 px copy of each stimulus into `gaze-by-scene/stim/`, and emits
`gaze-by-scene/data.json`. It links each trial to its heat map by `<slug>__<condition>.jpg`;
the heat maps themselves are rendered elsewhere and live in `gaze-by-scene/heat/`.

## ② `live-aoi/` — human / dog live AOI

Walk minutes **05:00 – 10:00**, both viewpoints side by side, every readout advancing with
the picture.

Why that excerpt: picked out of the full 35 minutes for high divergence together with few
seconds the segmentation judged too dark or occluded — 8 of these 300 seconds (2.7%) — and
all of it outdoors. The sedentary indoor block, 19.0–28.6 min, is excluded from every figure
in this project anyway.

| Area | What it shows | From |
| --- | --- | --- |
| Paired bars | each AOI class's share of each frame, both views | `aoi/aoi_shares.csv` |
| Openness / obstacle / nearest ground | monocular depth metrics | `aoi/depth_metrics.csv` |
| Divergence | total-variation distance between the two compositions | `aoi/divergence_tv.csv` |
| Motion / turn rate | 20 Hz IMU, averaged into the same 1 s bins | `imu/imu.csv` |
| Timeline grey band | a walking stop | `imu/stops.csv` |
| Timeline amber band | that second was judged dark or occluded | `aoi/divergence_tv.csv` |

The bars list every AOI class whose share peaks above 3% of either frame somewhere in the
excerpt — seven of the ten here. The three that do not clear it (`door`, `vehicle`,
`furniture`, all peaking at 2.3–2.7%) are named in a footnote under the bars rather than
silently dropped. The timeline behind the video can only carry one class legibly, so it
defaults to whichever one the two views disagree about most over this excerpt and the
**Timeline** control switches it.

The CSVs are 1 Hz. The page interpolates linearly between rows and then applies a centred
moving average whose width is on screen (default 3 s) — raw 1 Hz bars jump so hard the real
differences disappear. Each indicator's bar range is the p98 of that series over this
excerpt, printed under the bar, rather than an invented 0–1.

The dog's own fur (`animal`) is dropped and both panels renormalised, same as every figure
in `aoi/`.

Regenerate, including for a different stretch of the walk:

```bash
# 1. the clip: stacked 1920x2160 -> side by side 1600x450
ffmpeg -y -ss 300 -t 300 -i "<pet-vision-combined.mp4>" \
  -filter_complex "[0:v]crop=1920:1080:0:0,scale=800:450[t];\
[0:v]crop=1920:1080:0:1080,scale=800:450[b];[t][b]hstack=inputs=2[v]" \
  -map "[v]" -an -c:v libx264 -preset medium -crf 30 -pix_fmt yuv420p \
  -movflags +faststart docs/media/walk-05-10.mp4

# 2. the indicators
python3 scripts/export_aoi_video_web.py --start 300 --duration 300
```

Change `--start` and you must also change the `<source>` filename in
`live-aoi/index.html` and the paragraph at the bottom that names the window.
